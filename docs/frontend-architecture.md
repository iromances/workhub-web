# WorkHub 前端架构说明

## 1. 技术栈

- Vue 3
- TypeScript
- Vite
- Vue Router
- Pinia
- Element Plus
- Axios
- UnoCSS 或 Tailwind 二选一

当前建议：

- 第一阶段优先 `Element Plus + UnoCSS`。
- 原因是后台表单、表格、抽屉、对话框、树筛选、日期区间等场景占比高，Element Plus 更省建设成本。

## 2. 设计目标

1. 面向后台业务，强调密度、筛选、效率和可追踪性。
2. 页面状态简单清晰，避免把业务规则写散在组件里。
3. 所有状态流转必须通过明确的交互入口完成。
4. 所有外部来源数据都先进入待整理视图，再由用户确认。

## 5. 前端状态分层

全局状态：

- 当前登录用户
- token 和登录态
- 字典与通用枚举
- 全局筛选上下文

页面状态：

- 查询条件
- 分页
- 当前 tab
- 抽屉显隐
- 表单草稿

约束：

- 不把表单临时状态塞进全局 store。
- 不把复杂业务规则散落在组件模板中。
- API 请求参数和响应类型统一定义在 `types` 与 `api` 层。

## 6. 交互原则

1. 工作项详情页是核心工作面板，不把关键动作分散到多个页面。
2. 状态流转使用固定动作区，不允许自由修改状态字段后直接保存。
3. 待整理箱要同时展示原始内容、AI 建议、人工确认结果。
4. 高风险操作必须二次确认，例如拒绝、挂起、关闭、恢复暂停需求、删除附件。
5. 主布局导航切换应保留已访问页面的本地查询条件、分页、当前结果和抽屉状态，避免用户在跨菜单核对时丢失上下文。
6. 需求暂停必须通过显式入口录入暂停原因和暂停日期；恢复入口只能调用后端恢复到暂停前状态，页面需能在详情修改历史中查询暂停和恢复记录。
7. AI 接入配置的连通测试使用当前弹窗表单，不要求先保存；入口位于弹窗左下角，执行中、成功和失败结果常驻在按钮旁。API 与 CLI 页签独立保存本次弹窗内的反馈，列表不提供连通测试入口。

## 7. API 契约原则

1. 列表接口统一返回分页结构。
2. 枚举值传 code，页面展示用 label。
3. 状态变更、指派、转版本、转迭代等动作优先单独接口，不混在通用保存接口里。
4. 所有上传、下载、预览统一封装。

## 8. 质量要求

1. 路由按业务域划分，禁止按页面零散堆积。
2. 复杂表单使用 schema 或显式字段配置，不写超长模板。
3. 对筛选、看板、详情页建立基础组件复用层。
4. 前端页面开发前先对照 `project-charter.md` 检查是否超范围。

## 需求过程信息编辑

需求列表操作菜单通过“删除”上方的“编辑”入口打开“编辑过程信息”弹窗；详情顶部不展示该编辑按钮和独立预估工时汇总表，独立保存日期、实际及预估工时。开发/测试预估由用户输入，总预估由后端合计；人工修正后的需求预估独立于研发任务评估，不因保存任务被覆盖。保存失败保留表单，过期快照提示重新打开。沿用需求元信息编辑权限，修改留痕，不改变生命周期。

需求详情的基本信息页不再展示“关联研发任务”标题、表格及空态，原关联数据与任务评估能力保留。


## Codex 接入配置模型目录

AI 接入弹框中的 CLI 通道从后端 `/manage/system/ai-provider/codex-models` 读取运行环境的 Codex 模型及推理强度；打开弹框、启用 CLI、结束编辑命令或工作目录时加载，提供刷新及失败重试。模型改变时联动强度，查询本身不覆盖历史值。Codex 编码原样选择、保存及传给 CLI，历史全大写强度单独兼容。缺失的历史值提示“当前不可选”；原样修改其他字段可保存，新配置及改变环境或组合后必须先成功加载并选择有效组合。API 通道继续使用原字典。

## 布局与业务监测详情

主布局高度固定为视口高度，`html`、`body` 与 `#app` 使用完整高度，为页面内部滚动提供稳定的容器边界。

业务监测详情默认查询失败的 XXL-JOB 日志。打开详情时，以该监测项上次采集日期为结束日期，查询包含该日在内的七天；采集日期缺失或无法解析时使用最近七天。手工重置筛选时同样默认查询最近七天的失败日志，日期与日志状态仍可由用户调整。


## Agent 工作台（v4 扩展）

- 新增 `/agents`（agent:view），紧邻工作台入口，按 Agent → 任务 → 运行呈现。页面配置多 Agent、选择已有 AI、分派立即/周期任务、调整周期、查看独立运行、补充指令、取消和重试。
- 类型与 API 分别位于 `src/types/agent.ts`、`src/api/agent.ts`；页面放在 `src/views/agent/`。表单及选择状态留在页面，不新增全局 store。
- 接口使用 `/api/agents`、`/api/agents/options`、`/api/agent-tasks`；后端返回已授权的选择项，不向页面发送密钥、执行命令或全局 MCP Token。写入携带版本，任务分派/运行/补充使用请求标识；网络重试沿用原标识。
- 运行和产物只呈现后端事实；`CANCELLING` 表示正在停止，`WAITING_RESOURCE` 表示需处理执行资源或核实外部状态。不能把已取消请求显示为已停止。`AI_REPORT` 与平台测试/部署证据分别标注。
- 页面离开或被 KeepAlive 停用时停止轮询，恢复时重新读取状态。异步请求绑定当前 Agent/任务/运行，旧响应不能覆盖新选择。时间字段来自 UTC，显示为浏览器本地时间。
- 分支、Jenkins 审核和上线验证入口随后端相应契约接入；没有实际结果时不补造成功记录。

- Agent 工作台增加授权范围内的巡检问题面板，类型/API 位于 `autonomy.ts`，调用 `/api/autonomy/cases`。按业务线/环境筛选，问题详情分别分页查看监测证据与不可变 AI 方案；当前只读查看，不增加未接入的批准或关闭动作。新选择和页面停用使旧请求失效，来源权限及范围由后端再次校验。

- 运行详情增加“候选变更”页签，契约为 `/api/agent-changes` 列表及 `/{id}` 详情，使用 `agentChange.ts` 类型/API 和 `AgentChangesPanel.vue`。展示多仓库准确提交、拟交付分支、依赖顺序、差异及 AI 验收/回退建议；候选当前性和审核条件由后端返回。页面不把分支名当作远端交付证据，当前未接入审核动作。请求失败清除旧内容，切换运行及 KeepAlive 停用丢弃旧响应。

- 候选详情通过 `/api/agent-changes/{id}/deliveries` 独立读取每仓库交付记录，展示实际分支、目标分支、MR 链接、最后核验时间及未知/冲突等状态；未登记与读取失败分开显示。交付请求失败清除旧交付内容但保留已成功读取的清单，切换版本/运行后丢弃旧响应。MR 链接只开放 http(s)，不提供页面直接推送或发布按钮。

- 候选详情增加 `AgentReleasesPanel.vue`，使用 `agentRelease.ts` 类型/API 读取 `/api/agent-release-plans` 的列表和冻结材料、平台证据、Job 依赖、审核历史及部署状态。有 `autonomy:release:review` 权限的用户可填写意见并显式批准/驳回；批准二次确认提示 WorkHub 将自动调用整组 Jenkins Job。请求固定材料摘要、版本和幂等标识，结果未知时重试原请求；切换候选/计划或停用组件丢弃旧响应。页面不直接调用 Jenkins，不能以构建成功替代部署或业务验证。


### 2026-11-04 ZCode CLI 接入补充

AI 接入配置区分 Codex 与 GLM ZCode 的 CLI 协议。ZCode 使用已有程序、可选 Node 运行时、既有 Provider 定义和认证配置，模型/推理档位按 ZCode 实际配置填写；不会套用 Codex 模型目录或触发软件安装。Agent 工作台原生任务统一使用获授权的 WorkHub 工具，连接测试仅作最小模型请求。旧本地研发分析场景暂不提供 ZCode 选项；测试环境的 Jenkins 独立构建测试与人工发布审核分别呈现，本次不执行生产构建测试。
